# Data Understanding Module

## What it is
`data_understanding` is the diagnostic profiling stage that turns schema + raw data into model-facing column intelligence.

## What it does
- Reads semantic mapping generated by schema inference.
- Produces per-column quality/profile records.
- Computes relationship-level signals (correlation pairs, redundancy, dependency graph, pruning hints).
- Writes everything to `data/column_inspection.jsonl`.

## How it works
1. `run_data_understanding(dataset_path)` loads data and schema mapping.
2. It computes dataset-level relationships (`correlation_pairs`, `redundant_features`, `derived_linear_relationships`, `feature_dependency_graph`, `pruning_plan`).
3. It loops through each column and computes technical + semantic diagnostics (missing pattern, outliers, transform hints, encoding need, modeling hints, etc.).
4. Output is appended as a single inspection payload.

## Important functions
- `pipeline.run_data_understanding(...)`: main orchestration.
- `semantic_reader.get_semantic_mapping(...)`: lookup from `data_classification.jsonl`.
- `column_profiler.missing_pattern(...)`: missingness mechanism signal.
- `column_profiler.distribution_shape(...)`, `outliers_present(...)`, `transform_hint(...)`.
- `feature_relationships.pruning_plan(...)`: proposes correlated-feature drops.
- `exporter.export_column_inspection(...)`: safe JSONL append with newline handling.
